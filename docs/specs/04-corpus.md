# The corpus

The frames every case runs on. Generated by `fpcompat/corpus.py` from one seed, written to Parquet and to CSV, described by a committed manifest with a digest per frame.

## The principle

A conformance suite finds bugs in proportion to how nasty its inputs are, and the inputs that find bugs are not large. Ten million rows of well formed float64 exercises the same three branches as a thousand rows of it. What finds bugs is a column that is all null, a column with one distinct value, a string of exactly twelve bytes, a group with one member, a window longer than the frame, and a float column holding a negative zero next to a NaN.

So the corpus is small and mean. Every frame is between 0 and 10000 rows, the whole thing is a few megabytes, and it is regenerated in under a second. Size belongs in firepanda-bench, where it is the point. Here it is a distraction that makes the suite slow enough that people stop running it.

## The frames

Every frame is named, and a case names the frames it wants. A case that names no frame runs on all of the ones matching its dtype requirements, which is the default and is how one case becomes forty comparisons.

**Shapes.** `empty` with zero rows and three typed columns. `single` with one row. `two` with two rows, because the off by one in a diff or a pct_change needs exactly two. `wide` with 200 columns and 5 rows, which is where a column-at-a-time implementation gets slow and where an axis argument gets confused. `tall` with 10000 rows and 3 columns.

**Numeric.** One frame per integer width including `Int128`, one per float width, each in three null shapes: no nulls, half null, all null. Float columns carry the six values that break naive code, which are NaN, positive and negative infinity, negative zero, the smallest denormal and the largest finite value, placed at known row offsets so a failure report can name them.

**Integer edges.** Minimum and maximum of every width in the same column as ordinary values, because a sum that promotes correctly and a sum that overflows look identical on random data.

**Strings.** `strings_ascii` with lengths 0 through 20, which straddles the 12 byte StringView discriminant deliberately. `strings_unicode` with combining characters, right to left text, emoji including a multi codepoint family sequence, and a Turkish dotless i so that `lower` and `upper` are not assumed to be inverses. `strings_null_heavy` where two thirds of the values are null and the empty string appears beside the nulls, because a library that confuses the two fails here and nowhere else. `strings_pattern` with values built to exercise regex: anchors, alternations, character classes, a value that is 500 characters of the same letter, and a value containing a null byte.

**Categorical.** Ordered and unordered, with an unused category present, with a null in the values, and with categories that are not in sorted order, because `sort_values` on an ordered categorical follows the category order and not the lexical one.

**Temporal.** Timestamps at second, millisecond, microsecond and nanosecond resolution, with and without a timezone, crossing a DST spring forward and a DST fall back in `America/New_York` and in `Australia/Lord_Howe`, which has a 30 minute offset change and finds assumptions that a whole hour was involved. Dates before 1970 and after 2262, the second of which is where a nanosecond timestamp overflows. Durations, positive and negative and zero.

**Keys.** Group by keys at three cardinalities: 10 groups, 1000 groups, and one group per row. Keys with a null. Keys with an empty string. A two column key where each column alone has duplicates. This is the shape from db-benchmark, at a size where the answer can be checked rather than fingerprinted.

**Nested.** List columns with an empty list, a null list, a list containing a null, and lists of varying length. Struct columns with a null struct, a struct with a null field, and a nested struct. These exist so the `.list` and `.struct` cases have something to run on, and pandas covers this thinly enough that several of them will be registered divergences.

## Generation

splitmix64 over a counter, the same generator `firepanda-bench` uses, for the same reason: it is a dozen lines, it produces the same stream from any language, and the Mojo driver can therefore generate an identical frame without reading a file. The seed is the hexadecimal digits of pi, which is the seed the bench repository already uses, and the two are deliberately the same constant so that a person reading both repositories does not have to wonder whether the difference is meaningful.

Edge values are not generated. They are written down as literals in `corpus.py`, placed at fixed offsets, and listed in the manifest. A random generator does not produce a negative zero, and a corpus that relies on one is a corpus that finds those bugs on a Tuesday in 2027.

## The manifest

`corpus/manifest.json` carries, per frame: the name, the row count, the column names and dtypes, the null count per column, the row offsets of the edge values, and a digest of the Arrow table. The runner verifies every digest before it runs a case and after each module of cases.

The manifest is committed. The Parquet files are not, because they are regenerated in a second and a binary in git is a binary in git forever. What being committed buys is that a change to the corpus is a reviewable diff: adding a frame or changing a null pattern shows up as a manifest change in the pull request, and a conformance number that moved because the inputs moved is visible rather than mysterious.

## Growth

The corpus is extended when a bug escapes it, and the pull request that fixes a conformance bug in firepanda adds the input that would have caught it. That rule is the entire maintenance policy, it is the same one document 09 in the parent folder sets for the library's own tests, and it is why the corpus will be twice this size in a year and will still run in a second.

The corpus is not extended by adding rows. If a bug needs a million rows to reproduce it is a chunking or a parallelism bug, and those belong in the library's own stress suite where the machinery for them already exists.
