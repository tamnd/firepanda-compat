# Changelog

All notable changes to this repository are recorded here. The format is
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and this repository
follows [semantic versioning](https://semver.org/spec/v2.0.0.html), where the
public interface is the case id namespace, the result file schema and the
divergence registry format.

- `in_process` on a case declaration, which says that an answer can only be reached through the subject's own Python module. The routing rule set by spec 25 is the level, L0 and L1 to the module because only reflection answers a reflection question, and spec 35 moved L4 across for the same kind of reason. - Spec 36, which is why the exception exists. `DataFrame.filter`, `DataFrame.select_dtypes` and `DataFrame.truncate` landed in firepanda [#517](https://github.com/tamnd/firepanda/pull/517) and live only in the Python layer, because the rules they follow are pandas compatibility rules rather than dataframe operations. `select_dtypes` is the clearest of the three: it matches column types against numpy's type tree, a tree where a duration is a signed integer and a timestamp is not a number, and the core has no opinion about numpy and should not grow one. Arrow's `take` has no kernel for the view layouts, so the runner wrote "the comparison itself raised" into the result file, which is the harness admitting a bug of its own in the place a reader goes for facts about the engine. firepanda's strings are views, so this was every grouped comparison on a text key rather than an exotic corner. View columns are widened to their large variants before the take, which loses nothing, since `canonical_type` already folds all three string widths into one name on the grounds that pandas has one string dtype.
- A comparison between two answers with different numbers of index levels raised `IndexError` out of pyarrow instead of reporting a difference, because the column loop is indexed by the pandas side's shape and ran off the end of the narrower one. It was found the first time a real subject produced an answer with no index, which is `DataFrame.tail` against firepanda, and until it was fixed the runner reported it as a bug in `fpcompat.compare`, which it was.
